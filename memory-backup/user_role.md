# 用户角色

## 团队结构
企划团队（Planning Team）涵盖五个职能模块：
- 采购
- 物控
- 仓库
- 生管
- **订单管理** ← 用户负责

## 用户职责：订单管理与订单交付
核心工作流：
1. **订单接收** — 收到客户订单，进行数据检查
2. **ACK/NACK 判断** — 验证订单信息完整性，决定确认(ACK)还是拒绝(NACK)
3. **缺料能见度** — 对订单涉及物料的短缺情况有预判能力
4. **开立工单(MO)** — 在正确的时间点创建生产工单
5. **Input → Output → 出货** — 每个节点严格把关

## SPEC 的定位
Dell SPEC 文档是客户给到团队的系统 Enable 文件。团队基于 SPEC 搭建自己的流程和系统逻辑。用户需要从 SPEC 中提取：
- 操作流程和规则
- 系统判断逻辑（如 ACK/NACK 条件）
- 时间节点和截止时间
- 异常处理路径

## 工作方式偏好
- 喜欢将 SPEC 拆解为可执行的操作手册和时间轴
- 需要 PPT 格式的 SOP 供日常作业参考
- 要求精确的时间节点和数据判断规则
- 关注"怎么做"胜过"是什么"
